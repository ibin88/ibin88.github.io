Control Systems · Case Study

Automated Weaving Control System

M.Eng thesis with Mr Trampoline Pty Ltd · RMIT University · 2026

A semi-automated industrial weaving machine whose heddle, rapier and comb mechanisms existed but moved independently. The brief: make them run as one coordinated, repeatable automated system.

Approach

Treated as a mechanically-coupled, open-loop sequencing problem on stepper-driven axes. Each axis was characterised on the bench (homing, limit handling, trapezoidal motion), then folded into a master sequencer driving the full pick cycle (shed open → rapier insertion → beat-up → shed exchange) directly from an Arduino, no PC in the loop.

Outcome

A repeatable, collision-free weaving cycle across all three axes, with deterministic homing and over-travel protection, and a fab-ready control board: a working baseline the next iteration builds on.

Architecture
4 stepper axes, 1 sequencer
Hardware
Custom Arduino control PCB
Result
Collision-free pick cycle
AI-Generated CAD · Verification

ZooMounter: AI-Generated Mounting Plate Verification

Zoo API Makeathon · 2026

A tool that turns vague mounting problems into engineered reality: specify a motor, bearing, or compute board, a load, and a material; the system generates a mounting plate via Zoo's Agent API, then independently verifies the AI-generated geometry against structural and positional specs before returning a verified CAD model.

The problem

AI-generated CAD is impressive but untrustworthy: a plausible-looking mounting plate might have holes in the wrong place or insufficient thickness under load. This tool closes that gap by embedding engineering checks (cantilever bending, bolt-hole position verification, bounding-box constraints) directly into the generation pipeline.

The approach

Integrate Zoo's three APIs meaningfully: Agent API generates KCL from a fully-constrained spec (every hole coordinate explicit, not vague); Engine API executes the KCL into a STEP export; File Format API then runs three independent verification checks (hole positions, bounding box, volume) that catch both AI mistakes and geometry shifts.

Robotics · Published Research

Dual-Arm Coordinated Robot

JAMRIS, 2019 · NIT Calicut, India

Many everyday tasks need two hands working together, which is difficult for people with limb loss or motor impairment. This project showed that coordinated bimanual manipulation is achievable with a compact, low-cost anthropomorphic robot.

System architecture

Each arm used anthropomorphic joints chosen for predictable kinematics and manufacturability rather than maximum degrees of freedom, keeping control simple and behaviour repeatable.

Coordination strategy

The two arms were treated as a single coupled unit: one arm stabilises the object while the other solves the combined kinematic chain, giving collision-aware coordinated motion without heavy computation or learning-based methods.

Modelling · Machine Learning

Engine Emissions Estimation

TNO & HAN University, Netherlands · 2021-2022

A MATLAB application that estimates instantaneous tailpipe emissions for heavy vehicles at low speed, to understand how a change in operating regime, such as electrification, would shift emissions over time.

What it estimates

CO₂, NOₓ and ammonia under specific thermal conditions, computed at each time step from engine speed and load, pre- and post- exhaust-treatment states, and other operating indicators.

Modelling approach

Linear time-series (ARX) models could not capture the non-linear, state-dependent behaviour, so the model was extended to a recurrent neural network that tracks transitions between operating states.

CO₂ · NOₓ · NH₃
Models
ARX → recurrent neural network

Systems · Feasibility Study

Wind-Turbine-Blade Transport

Ter Linden & HAN University, Netherlands · 2020

Moving 120 m turbine blades through constrained roads is a systems problem: vehicle geometry, articulation, steering limits and road layout all interact. This decision-support study assessed whether a truck-and-dolly system could negotiate real road geometries within mechanical and spatial limits.

Method

The transport system was represented as a kinematic model: first a single-line stick model for gross articulation, then an extended representation with axle positions and wheel tracks.

Evaluation

Assessed across representative low-speed manoeuvres (large roundabouts and 90° turns) for relative articulation angles and swept-path envelopes, including whether a powered dolly would be required.

Payload
120 m turbine blade
Model
Stick → axle & wheel-track
Assessed
Swept paths, articulation, dolly
